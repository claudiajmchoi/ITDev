# PRD — 아이디어 사업화 성공 가능성 분석 서비스

> **작성일:** 2026-03-13
> **버전:** v0.1 (초안)
> **상태:** 인터뷰 기반 초안 — 검토 후 확정 필요

---

## 1. 개요 (Overview)

### 1.1 서비스 한 줄 정의

> 누구나 사업 아이디어를 입력하면, 멀티 LLM 앙상블 AI가 **시장성 · 경쟁 강도 · 수익 모델**을 종합 분석해 **0~100점의 사업화 성공 확률 점수**와 업종별 맞춤 인사이트를 제공하는 웹 서비스.

### 1.2 핵심 문제 정의

- 예비 창업자 / 스타트업 팀은 아이디어의 실현 가능성을 객관적으로 검증할 저렴하고 빠른 수단이 없다.
- VC 컨설팅은 비용이 크고, 검색은 단편적이며, ChatGPT는 구조화된 평가 기준을 제공하지 않는다.
- **이 서비스는 "5초 안에 전문가 수준의 사업 타당성 스코어카드"를 제공한다.**

### 1.3 성공 지표 (KPI)

| 지표                           | 목표 (출시 후 3개월)          |
| ------------------------------ | ----------------------------- |
| MAU                            | 5,000명                       |
| 분석 완료율 (입력 → 결과 확인) | ≥ 70%                         |
| 유료 전환율 (크레딧 구매)      | ≥ 5%                          |
| 평균 분석 응답 시간            | ≤ 5초 (스트리밍 첫 토큰 기준) |

## 2. 타깃 사용자

### 2.1 주요 사용자

| 페르소나                   | 설명                                                            |
| -------------------------- | --------------------------------------------------------------- |
| **예비 창업자 (Primary)**  | 창업을 고민 중이나 아직 시작 전, 아이디어 검증에 대한 니즈 높음 |
| **현직 스타트업 팀**       | 피벗 / 신규 기능 아이디어를 빠르게 검증하고 싶은 팀             |
| **사이드 프로젝트 개발자** | 개인 프로젝트의 사업성 판단이 필요한 개발자                     |

### 2.2 포지셔닝

- **B2C 대중화** — 전문 지식 없이 누구나 5분 안에 사용 가능

- **MVP 이후 한국 시장 검증 → 글로벌 확장** 순서

## 3. 핵심 기능 (MVP v1 Scope)

> **MVP 기준: 비로그인 사용자도 분석 가능. 이력 저장은 로그인 필요.**

### 3.1 Feature 1 — 아이디어 입력

**입력 방식: 자유 텍스트 + 구조화된 폼 (탭 전환)**

#### 자유 텍스트 모드

```
[                                                    ]
  "내 아이디어를 자유롭게 설명해주세요.
   예: '직장인을 위한 점심 구독 서비스로, 주변 식당과
       연계해 매일 랜덤 도시락을 배달해줍니다.'"
                                    [분석 시작하기 →]
```

#### 구조화된 폼 모드

| 필드          | 필수 여부 | 설명                   |
| ------------- | --------- | ---------------------- |
| 아이디어 이름 | 선택      | 서비스/제품명          |
| 문제 정의     | **필수**  | 어떤 문제를 해결하는가 |
| 해결 방법     | **필수**  | 어떻게 해결하는가      |
| 타깃 고객     | 선택      | 주요 사용자 집단       |
| 수익 방법     | 선택      | 어떻게 돈을 버는가     |
| 업종/카테고리 | 선택      | AI 업종별 분석에 활용  |

**모호한 입력 처리 (엣지 케이스 #1):**

1. AI가 입력을 분석 후 정보가 부족하면 **2~3개의 보완 질문 제시**
2. 질문에 답한 후 분석 시작 OR 그냥 진행(부분 분석 + 불확실성 경고)
3. 명백히 너무 짧은 경우(10자 미만) → 재입력 요청

### 3.2 Feature 2 — AI 분석 엔진

#### 멀티 LLM 앙상블 전략

```
[사용자 입력]
      │
      ▼
[프리프로세싱 레이어]
  - 언어 감지 (한국어 우선)
  - 업종 자동 분류
  - 입력 품질 평가 (충분 / 보완 필요)
      │
      ▼
[병렬 LLM 호출]
  ┌── Model A (Claude): 시장성 + 경쟁 분석
  ├── Model B (GPT-4o): 수익 모델 분석
  └── Model C (Claude): 종합 인사이트 + 위험 요소
      │
      ▼
[앙상블 집계 레이어]
  - 가중 평균 점수 산출
  - 불일치 항목 재검증
  - 신뢰도 메타데이터 생성
      │
      ▼
[결과 출력 (스트리밍)]
```

#### 평가 3대 차원 및 가중치 (초안)

| 차원                 | 가중치 | 세부 항목                                  |
| -------------------- | ------ | ------------------------------------------ |
| **시장 규모 / TAM**  | 40%    | 시장 크기, 성장률, 타깃 접근 가능성        |
| **경쟁 강도**        | 30%    | 경쟁자 수, 진입 장벽, 차별화 가능성        |
| **수익 모델 명확성** | 30%    | 수익 발생 경로, BEP 현실성, 반복 구매 여부 |

> **트레이드오프:** 가중치를 고정하면 업종별 왜곡 발생 가능. → 업종별 동적 가중치 적용 (v2 검토)

#### 최종 점수 산출

```
종합 점수 = (시장점수×0.4) + (경쟁점수×0.3) + (수익점수×0.3)

등급 기준:
  90~100 : S  — "강력 추천, 즉시 실행 가능"
  75~89  : A  — "유망, 일부 보완 필요"
  60~74  : B  — "가능성 있음, 핵심 리스크 해소 필요"
  45~59  : C  — "도전적, 대규모 검증 필요"
  0~44   : D  — "현시점 사업화 어려움"
```

### 3.3 Feature 3 — 결과 화면

#### 레이아웃 구성 (3-Zone)

```
┌──────────────────────────────────────────────────┐
│  ZONE A: 히어로 스코어                            │
│  ┌──────────────┐   ┌────────────────────────┐   │
│  │  🎯 73점      │   │  레이더 차트             │   │
│  │  등급: B+     │   │  (시장성 / 경쟁 / 수익)  │   │
│  └──────────────┘   └────────────────────────┘   │
├──────────────────────────────────────────────────┤
│  ZONE B: 차원별 상세 분석                         │
│  시장 규모 ████████░░ 78점 — 분석 텍스트...      │
│  경쟁 강도 ██████░░░░ 62점 — 분석 텍스트...      │
│  수익 모델 █████████░ 85점 — 분석 텍스트...      │
├──────────────────────────────────────────────────┤
│  ZONE C: AI 종합 인사이트                         │
│  ✅ 강점 3가지                                   │
│  ⚠️  핵심 리스크 2가지                            │
│  📋 다음 액션 아이템 3가지                        │
│                                                  │
│  [PDF 다운로드]  [다시 분석하기]  [공유하기]      │
└──────────────────────────────────────────────────┘
```

**실시간 스트리밍:** 분석 시작 후 각 Zone이 순차적으로 스트리밍되며 채워짐. 전체 목표 응답 시간 **5초 이내**.

---

### 3.4 Feature 4 — 분석 이력 저장 / 조회

- **비로그인:** 브라우저 LocalStorage에 최근 3건 임시 저장
- **로그인 후:** Supabase DB에 영구 저장, 마이페이지에서 전체 이력 조회
- 이력 카드: 아이디어 요약, 점수, 등급, 분석일, 재분석 버튼

---

### 3.5 Feature 5 — PDF 리포트 다운로드

MVP에서 포함. A4 2~3페이지 기준:

- 표지: 아이디어 이름, 점수, 날짜
- 차원별 점수 + 레이더 차트 이미지
- AI 분석 텍스트 전문
- 다음 액션 아이템

> **기술 구현:** `@react-pdf/renderer` 또는 `html2canvas + jsPDF` 검토. 서버사이드 생성 vs 클라이언트사이드 생성 트레이드오프 존재 (→ 4. 기술 아키텍처 참고)

## 4. 기술 아키텍처

### 4.1 스택

| 레이어    | 기술                       | 선택 이유                   |
| --------- | -------------------------- | --------------------------- |
| Frontend  | Next.js 14 (App Router)    | SSR, SEO, Vercel 배포       |
| Styling   | Tailwind CSS               | 빠른 UI 개발                |
| Backend   | Next.js API Routes         | 별도 서버 불필요, 단일 배포 |
| Database  | Supabase (PostgreSQL)      | 인증 + DB + Storage 통합    |
| AI        | Claude API + OpenAI GPT-4o | 멀티 LLM 앙상블             |
| 스트리밍  | Server-Sent Events (SSE)   | LLM 스트리밍 응답           |
| PDF       | `@react-pdf/renderer`      | 서버사이드 PDF 생성         |
| 배포      | Vercel                     | Next.js 최적화 호스팅       |
| 결제 (v2) | Stripe 또는 토스페이먼츠   | 크레딧 구매                 |

### 4.2 데이터 모델 (초안)

```sql
-- 분석 요청
analyses (
  id          uuid PRIMARY KEY,
  user_id     uuid REFERENCES users(id) NULLABLE,  -- 비로그인 허용
  session_id  text,                                  -- 비로그인 추적용
  input_text  text NOT NULL,
  input_form  jsonb,                                 -- 구조화 폼 데이터
  industry    text,                                  -- 업종 분류 결과
  result      jsonb,                                 -- 전체 분석 결과
  score       integer,                               -- 0~100
  grade       text,                                  -- S/A/B/C/D
  model_meta  jsonb,                                 -- 사용 모델, 신뢰도
  created_at  timestamptz DEFAULT now()
)

-- 크레딧 (v2)
credits (
  user_id     uuid REFERENCES users(id),
  balance     integer DEFAULT 3,
  updated_at  timestamptz DEFAULT now()
)
```

### 4.3 API 설계 (핵심 엔드포인트)

| Method | Path                    | 설명                          |
| ------ | ----------------------- | ----------------------------- |
| `POST` | `/api/analyze`          | 분석 시작 (SSE 스트리밍 응답) |
| `GET`  | `/api/analyses`         | 이력 목록 조회 (인증 필요)    |
| `GET`  | `/api/analyses/:id`     | 특정 분석 결과 조회           |
| `GET`  | `/api/analyses/:id/pdf` | PDF 다운로드                  |
| `POST` | `/api/clarify`          | 보완 질문 응답 후 재분석      |

### 4.4 주요 트레이드오프

| 결정 사항          | 선택                   | 대안             | 이유                          |
| ------------------ | ---------------------- | ---------------- | ----------------------------- |
| 멀티 LLM 병렬 호출 | ✅ 채택                | 단일 LLM         | 정확도 향상, 비용 증가 감수   |
| PDF 생성 위치      | 서버사이드 (API Route) | 클라이언트사이드 | 보안, 품질 일관성             |
| 비로그인 허용      | ✅ MVP에서 허용        | 필수 로그인      | 진입 장벽 최소화              |
| LLM 스트리밍       | SSE                    | WebSocket        | 단방향 스트림에 SSE가 더 단순 |
| 가중치 고정        | MVP 고정               | 업종별 동적      | MVP 범위 최소화, v2로 연기    |

## 5. UX 플로우 (Happy Path)

```
[랜딩 페이지]
      │ CTA 클릭
      ▼
[입력 화면]
  - 탭: 자유 텍스트 / 구조화 폼
  - 아이디어 입력
  - "분석 시작" 버튼
      │
      ▼
[AI 보완 질문 (조건부)]
  - 입력 부족 시 2~3개 질문
  - 사용자가 답변 OR 스킵
      │
      ▼
[분석 중 — 스트리밍 로딩]
  - 진행 단계 표시: "시장 분석 중..." → "경쟁 분석 중..." → "종합 중..."
  - 히어로 점수 영역 먼저 채워짐 (빠른 피드백)
      │ < 5초
      ▼
[결과 화면]
  - Zone A: 점수 + 등급 + 레이더 차트
  - Zone B: 차원별 바 차트 + 설명
  - Zone C: 강점 / 리스크 / 액션 아이템
  - 하단: PDF 다운로드 / 재분석 / 공유
      │
      ├── [로그인 없이 종료]
      │     └── LocalStorage에 임시 저장
      │
      └── [로그인 / 회원가입]
            └── DB에 이력 저장 → 마이페이지
```

## 6. 수익화 모델

## 7. 엣지 케이스 및 예외 처리

| 케이스                                   | 처리 방식                                     |
| ---------------------------------------- | --------------------------------------------- |
| 입력 10자 미만                           | 재입력 요청 메시지 표시                       |
| 모호한 아이디어                          | AI 보완 질문 2~3개 제시 → 답변 후 재분석      |
| LLM API 타임아웃                         | 단일 모델로 폴백, 결과에 신뢰도 경고 표시     |
| 불법/윤리 위반 아이디어                  | 분석 거부 + 안내 메시지, 크레딧 미차감        |
| LLM 결과 불일치 (모델 간 점수 차 > 20점) | 재호출 1회 후 평균, 불확실성 배지 표시        |
| PDF 생성 실패                            | 재시도 버튼 + 텍스트 복사 대안 제공           |
| 네트워크 단절 (스트리밍 중)              | SSE 재연결 로직 + 마지막 수신 지점부터 재시작 |

## 9. 차별화 전략

### 9.1 결과의 신뢰성 확보

- 분석 결과 하단에 **"어떤 근거로 이 점수를 산출했나요?"** 섹션 제공
- 사용된 LLM 모델, 참조 데이터 카테고리 표시
- 신뢰도 메타데이터 (모델 간 일치율) 시각화

### 9.2 업종별 맞춤 분석

- 입력 아이디어에서 업종 자동 분류 (e-commerce, SaaS, F&B, EdTech 등)
- 업종별 특화 평가 항목 동적 추가
  - e.g., F&B: 위생/허가 리스크 추가 평가
  - e.g., SaaS: 네트워크 효과 / 전환 비용 평가
